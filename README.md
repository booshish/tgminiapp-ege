# Точка — демо подготовки к ОГЭ и ЕГЭ

Мобильное веб-приложение на Next.js, TypeScript и Tailwind CSS. Интерфейс на русском, тёплая светлая тема, адаптация для телефона, iPad и компьютера. Формулы отображаются через KaTeX с доступной разметкой MathML, рисунки построены в SVG. Telegram пока не подключён.

**Работаешь только с iPad?** Для просмотра сайта не нужен терминал: в проект добавлена автоматическая сборка GitHub Pages. Порядок нажатий описан ниже в разделе «Открыть и обновлять сайт только через GitHub». Сначала изменения должны попасть в основную ветку репозитория.

## Что доступно бесплатно

- Вся демотеория: **8 тем и 16 пошаговых примеров** — обыкновенные и десятичные дроби, проценты, линейные и квадратные уравнения, степени и корни, геометрия, вероятность.
- **24 задачи** по этим темам. В каталоге можно вручную выбрать ОГЭ или ЕГЭ, математику, тему и тип задания, затем открыть практику или материал теории. Банк показывает общую математическую базу для обоих экзаменов и не является полным экзаменационным курсом.
- Проверка ответа с результатом «Верно!» или «Неверно». Пустой или неподходящий по формату ввод не записывается как попытка.
- Пошаговое решение открывается **только после проверки и по желанию**, отдельной кнопкой. Переход к следующему заданию также выполняется вручную.
- Десятичная запятая, точка, обычные дроби и наборы корней в заданиях с несколькими ответами. Например, `0,8`, `0.8` и `4/5` считаются равнозначными; правила ввода указаны рядом с полем.
- Гостевой профиль, выбор экзамена, стандартный или крупный текст, удаление данных браузера.

Лимитов попыток, игровых жизней и дневных ограничений нет. Банк конечный: после его прохождения доступные задания повторяются. Новые задачи не генерируются; повторять существующие можно без ограничений.

## Premium: только демонстрация для разработки

По умолчанию работает **Free**. Страницы Premium объясняют будущие возможности, но не продают и не активируют подписку. Работающей оплаты нет.

В специальном режиме можно проверить подробные результаты, историю ошибок, динамику по датам и панель тренера на основании ответов, сохранённых в этом браузере. Тренер отмечает тему после как минимум трёх проверенных ответов, если хотя бы два неверны, и предлагает обычную теорию или практику по выбранной теме. Это простое правило, а не диагностика знаний, оценка готовности к экзамену или персональный учебный план.

Для показа переключателя разработчика запустите приложение с переменной окружения:

```bash
NEXT_PUBLIC_ENABLE_PREMIUM_DEMO=true npm run dev
```

Откройте **Профиль → Режим для разработчика → Включить демонстрационный Premium**. Переключение действует только до перезагрузки страницы: после неё снова включается Free. Ответы при этом сохраняются.

Для рабочей сборки переменная задаётся **во время сборки**, поскольку Next.js встраивает публичные переменные в клиентский код:

```bash
NEXT_PUBLIC_ENABLE_PREMIUM_DEMO=true npm run build
npm start
```

Без переменной или при её значении, отличном от `true`, переключатель скрыт. Это клиентская демонстрация без серверной защиты доступа. В приложении нет авторизации, оплаты, серверной подписки, внешней базы данных, синхронизации между устройствами или ИИ. Автоматическая диагностика пробелов, адаптивный подбор и настоящий персональный план ещё не реализованы.

## Данные и результаты

В localStorage сохраняются выбранный экзамен, размер текста, последнее задание и учебные события:

- проверенный ответ, его корректность и фактическое время проверки;
- идентификаторы задачи, темы, типа задания, экзамена и предмета;
- факт открытия решения, время просмотра и ссылка на соответствующую попытку. Повторное открытие решения той же попытки не создаёт второй просмотр.

События накапливаются и в Free; подробное представление результатов сейчас проверяется в демонстрационном Premium. Данные на сервер не отправляются. «Решено заданий» — число уникальных задач хотя бы с одним правильным ответом. Доля верных — количество верных ответов, делённое на число проверенных попыток; просмотр решения не является ответом. Пустые состояния показываются без выдуманных результатов.

Старые итоги из первой демоверсии автоматически переносятся отдельно. Неизвестные ответы, даты и просмотры не восстанавливаются искусственно; старые суммарные записи не появляются в истории ошибок и графике по датам. Даты новых событий сохраняются в ISO-формате, а график группируется по дням UTC.

Для удаления откройте **Профиль → Удалить локальные данные** и подтвердите действие. Удаляются ответы и выбранные настройки этого браузера, включая старые сохранения. Данные доступны только в том же браузере по тому же адресу сайта. Очистка браузера может их удалить; другой домен, устройство или браузер получит отдельное сохранение. Если localStorage недоступен, приложение предупреждает, что сохранение между запусками не гарантируется.

## Как открыть сайт

### На iPad через облачную среду

Откройте проект в среде с Node.js и терминалом. В папке проекта выполните:

```bash
npm ci
npm run dev
```

Если среда предоставляет **Preview / «Предпросмотр» / Ports**, выберите **порт 3000** и откройте выданную ссылку в Safari. Наличие этой кнопки, публичного адреса и срок работы превью зависят от среды; код не создаёт публичную ссылку автоматически.

`localhost:3000` на iPad означает сам iPad, а не удалённый сервер. ZIP с исходниками тоже не запускает Next.js самостоятельно. Вручную редактировать файлы для обычного запуска не требуется.

### На компьютере

Используйте Node.js 22 LTS. В терминале в папке проекта выполните те же `npm ci` и `npm run dev`, затем откройте **http://localhost:3000** на этом компьютере.

Для просмотра на iPad в той же сети Wi-Fi откройте `http://IP-АДРЕС-КОМПЬЮТЕРА:3000`, например `http://192.168.1.20:3000`. Компьютер должен продолжать работать, а доступ к порту должен быть разрешён настройками сети.

### Рабочая сборка

```bash
npm run build
npm start
```

`npm start` запускает предварительно собранное приложение на порту 3000. Перед этим остановите `npm run dev`, если он занимает этот порт. Обычная сборка не включает демонстрационный Premium без соответствующей переменной окружения.

## Открыть и обновлять сайт только через GitHub

На iPad открой GitHub в Safari. Настройка выполняется один раз, бесплатный публичный репозиторий подходит.

1. Открой [настройки Pages проекта](https://github.com/booshish/tgminiapp-ege/settings/pages). В разделе **Build and deployment → Source** выбери **GitHub Actions**. Старую ветку `gh-pages` удалять не нужно.
2. Изменения этой задачи должны попасть в ветку **main**. Если Codex показывает кнопку **Create PR / «Создать PR»**, нажми её, открой полученный запрос на GitHub и выбери **Merge pull request → Confirm merge**. Не нужно переносить файлы по одному.
3. Открой [Actions](https://github.com/booshish/tgminiapp-ege/actions) и запуск **«Публикация Точки»**. Дождись зелёной галочки у обоих заданий — проверки/сборки и публикации.
4. Вернись в **Settings → Pages** и нажми **Visit site**. Ожидаемый адрес проекта — **https://booshish.github.io/tgminiapp-ege/**. Только успешный запуск публикации подтверждает, что новая версия доступна по этому адресу.

После этого каждое обновление `main` автоматически проверяет и публикует сайт. Вручную собирать или загружать `out` не нужно. Для повторного запуска открой **Actions → Публикация Точки → Run workflow → main → Run workflow**. Эта кнопка появляется после добавления workflow в `main`.

Если запуск красный, открой его и посмотри первый неуспешный шаг. Ошибка **Get Pages site failed** обычно означает, что в **Settings → Pages** ещё не выбран **GitHub Actions**. После исправления нажми **Re-run all jobs**. Если среда `github-pages` ограничивает ветки, разреши ей публикацию из `main` в настройках среды репозитория.

В workflow явно выключен демонстрационный Premium. Секреты, отдельный хостинг и платные API для этой публикации не требуются. Учебные события остаются только в браузере посетителя и не попадают в артефакт сборки.

Если Codex не может отправить изменения из-за ошибки входа GitHub, сначала восстанови подключение GitHub в настройках Codex. Сам workflow не переносит локальные изменения в репозиторий. Не присылай пароли или токены в чат.

## Статическая сборка вручную — необязательный вариант

```bash
npm run build:pages
```

Команда создаёт статический сайт в папке `out`, включая `.nojekyll`, и настраивает пути `/tgminiapp-ege/`. **Это подготовка файлов, а не публикация.** Команда ничего не отправляет в GitHub и не включает Pages. Обычные `dev`, `build` и `start` продолжают работать без этого префикса.

Старый вариант публикации из ветки `gh-pages` тоже сохранён: в неё загружают содержимое `out`, а в **Settings → Pages** выбирают **Deploy from a branch → gh-pages → /(root)**. Его не нужно совмещать с вариантом **GitHub Actions** выше. Для другого репозитория перед ручной сборкой задайте `GITHUB_REPOSITORY` в формате `владелец/репозиторий`; имя репозитория определяет префикс ссылок.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
```

Для текущих изменений пройдены ESLint, TypeScript, **21 модульный тест**, обычная сборка и статическая сборка `build:pages`. Проверяются математические ответы, разные форматы ввода и наборы корней, целостность банка и теории, учебные события, миграция и повреждённые сохранения, подсчёты результатов. Тесты используют встроенный модуль Node.js, без отдельного тестового фреймворка.

В Chromium проверены все 24 задачи, 16 сочетаний экзамена/темы/типа и 35 последовательных бесплатных попыток без блокировок. Проверены скрытие статистики в Free, настоящие подсчёты и пустые состояния демонстрационного Premium, сохранение и удаление данных, отказ localStorage, клавиатура, навигация назад и формулы. На ширинах 320, 390, 768, 1024 и 1440 px переполнения страницы нет; отдельно проверен крупный текст. Автоматическая проверка axe выбранных экранов не выявила нарушений WCAG A/AA после исправлений. Это не заменяет ручную проверку на настоящем iPad: Safari и Telegram на устройстве в этой среде недоступны.

## Структура проекта

- `src/app/` — общий макет, метаданные, глобальные стили и страница приложения.
- `src/components/study-app.tsx` — оболочка приложения, маршруты и состояние демонстрационного режима.
- `src/components/screens/` — главная, каталог, теория, результаты, тренер, профиль и знакомство с Premium.
- `src/components/task-screen.tsx` — самостоятельная попытка решения с проверкой и добровольным разбором.
- `src/components/math-formula.tsx` — безопасное отображение формул через KaTeX и MathML.
- `src/components/illustrations.tsx` — собственные SVG-иллюстрации и математический рисунок.
- `src/lib/tasks.ts` — банк задач, типы заданий и проверка ответов.
- `src/lib/theory.ts` — темы, правила, формулы, примеры и связи с базовыми темами.
- `src/lib/learning-events.ts` — учебные события, чтение localStorage, миграция и расчёт результатов.
- `src/lib/navigation.ts` — типы маршрутов и названия разделов.
- `src/hooks/` — сохранение данных и история переходов.
- `scripts/test-demo.mjs` — модульные проверки.
- `scripts/build-pages.mjs` — подготовка статических файлов для GitHub Pages.
- `.github/workflows/pages.yml` — автоматические проверки, сборка и публикация при обновлении `main`.

Следующий шаг: пройти один учебный сценарий в Safari на iPad и оценить удобство чтения и ввода ответов.
