# Пакетный приём заданий — 2026-10-26

Это редакционный приём, **не автоматическая публикация**. Расширяет существующую систему staging (`stage-foundation-candidates.mjs`) для внешних JSONL, использует те же загрузчик данных, реестр прав, publication gate и SHA256-фингерпринты проверки. Не создаёт второй банк в приложении.

## Запуск и возобновление

`node scripts/import-tasks.mjs /path/tasks.jsonl pilot-001 /path/reviews.json`

Одна строка JSONL — один объект существующего `Task` из `src/lib/tasks.ts`. Сохраняются исходные поля целиком: условие, ответы, решения, требования, provenance, критерии, текстовые ресурсы, формулы и поддерживаемый тип геометрического рисунка. Новые номера/типы нельзя объявить произвольно: комбинация экзамена, уровня, года, версии, номера, части, темы и прототипа должна уже существовать в банке. Точная схема — `Task`, не параллельный формат.

Результат: `.content-staging/import-pilot-001/batch-N.json` и `checkpoint.json`. По умолчанию 200 строк на пакет, API допускает 1–300; `maxBatches` позволяет остановиться на границе пакета. Повторить ту же команду для продолжения. Изменение входного файла, корпуса, реестра прав или редакционного review требует нового job ID. SHA256 проверяется потоково; вход читается построчно. Существующий небольшой корпус используется только редактором для дедупликации, не отправляется ученику.

Один writer на job (lock-каталог). При аварии процесса оператор сначала убеждается, что процесс завершён, и удаляет **только пустой lock-каталог конкретного job**. Завершённые checkpoint/batch не удалять. Незакоммиченный хвост будет перечитан; запись checkpoint атомарна. Не редактировать файлы job вручную, не использовать символические ссылки в staging.

## Результаты

- `rejected`: битый JSON, обязательные поля, неизвестная привязка к модели, формат ответа, решение, баллы, KaTeX, неправильный ресурс/рисунок.
- `duplicates`: повтор ID, нормализованного условия или сходство множеств слов >=90%; близкие совпадения требуют редакционного решения (ложные совпадения возможны).
- `review`: проверка прав/материала не завершена. Не публикуется.
- `staged`: прошёл технический gate и имеется отдельная запись review с совпадающим SHA256. Это всё ещё редакционный staging, не опубликованное и не автоматически доказанное верное задание.

`reviews.json` — доверенный локальный массив: `{id, sha256, method, evidence}`. `method`: `source-answer-and-solution` или `independent-computation`; `evidence` — существующие относительные файлы проекта с результатами **реальной** проверки. Файл review не принимать от поставщика заданий без редактора. Наличие файла и SHA256 проверяется технически, достоверность заключения требует человека. Входной `validation.status` сам по себе не подтверждает правильность ответа.

Изображения/аудио/произвольные attachments пока не поддержаны существующей схемой и рендерером: такие записи отклоняются с `unsupported-media-needs-review`. Текстовые таблицы/длинные тексты хранятся без усечения в `resources`; полноценное отображение новых видов таблиц и медиа ещё требует отдельного адаптера и визуального QA. Рендер формул проверяется KaTeX; автоматической проверки ссылок на предложения или содержательной правильности всех дисциплин нет.

## Публикация и следующий этап (обновлено)

Для первого собственного пакета ленивое подключение теперь реализовано: `docs/pilot-publication.md`. JSONL intake по-прежнему только staging; в сайт включаются лишь явно проверенные релизные shards. Ниже сохранены ограничения предыдущего этапа; отсутствие lazy adapter к первому собственному пилоту уже не относится. Adapter происхождения стороннего контента и новые виды медиа пока не реализованы.

Staging не расположен в `public` и не импортируется в клиентский bundle. Первый собственный пакет выпускается отдельно через `release-task-pilot.mjs`: только одобренные записи, hash-pinned metadata index, загрузка по номеру и браузерная проверка. Для сторонних наборов ещё нужен adapter происхождения (нынешний `Task.source.kind` — `author`) и подтверждённая лицензия. Нельзя просто добавить весь staging в `tasks.ts`.
