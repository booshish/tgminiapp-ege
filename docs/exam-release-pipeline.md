# Проверка полного экзаменационного выпуска

На 21 октября 2026 года официальные спецификации и кодификаторы ФИПИ в этой среде не получены: сетевой запрос отклонён с `CONNECT HTTP 403`. Поэтому новый полный выпуск **заблокирован для всех трёх направлений**. Наличие предварительной структуры в старом коде не считается проверкой документа.

| Направление | Год текущей модели | Проверенные номера / баллы / время | Новые полные варианты |
| --- | --- | --- | --- |
| ОГЭ математика | 2026 | Не установлены | 0 |
| ЕГЭ математика, база | 2026 | Не установлены | 0 |
| ЕГЭ математика, профиль | 2026 | Не установлены | 0 |

Это состояние описано в `src/lib/exam-verification.ts`. Существующая предварительная практика не отключается и не объявляется официально сверенным экзаменом. Модель 2027 года не проверена.

## Проверка источников

```sh
node scripts/exam-release-check.mjs
node --test scripts/test-exam-release.mjs
```

Первая команда сейчас возвращает код **1** и три записи `blocked`. Это ожидаемая остановка выпуска, а не ошибка действующего учебного интерфейса. Обычная сборка приложения не снимает эту блокировку. Для сохранения машинного отчёта можно указать `--report docs/exam-release-status.json`.

После получения документов редактор готовит JSON-массив `VerifiedExamManifest` для трёх направлений и запускает:

```sh
node scripts/exam-release-check.mjs --manifest docs/official/reviewed-manifests.json
```

Для каждого направления необходимы:

1. Точные год, экзамен и уровень; официальные спецификация и кодификатор, для развёрнутых ответов — применимые критерии. В каждой записи нужны название, исходный HTTPS URL ФИПИ, локальный путь и SHA-256 файла.
2. Ручная сверка каждого номера, части, формата ответа, максимума баллов, проверяемых навыков и подтем. Время, инструкции, разрешённые средства и группы с общим условием также берутся из документа, а не из старой конфигурации.
3. Отдельная запись ручной сверки с автором, датой и ссылками на страницы документов. Контрольная сумма связывает запись с конкретными байтами, но сама по себе **не подтверждает содержание PDF**.
4. Локальные доказательства в `docs/official/`. Они исключены из Git по умолчанию: доступность документа для чтения не разрешает его перепубликацию. Для включения чужих учебных материалов нужен отдельный допуск через `source_registry` и проверку прав.

Валидатор отклоняет неполные таблицы, несовпадающие экзамены/годы/уровни, неверную сумму баллов, неизвестные критерии, отсутствующие файлы и несовпадающие SHA-256. Он не загружает документы автоматически и не выдаёт машинную проверку полей за экспертную сверку.

## Воспроизводимые варианты

`src/lib/exam-variant-manifest.ts` — инструмент редакционной сборки для Node.js, **не клиентский модуль**. После успешной проверки документов:

- `buildFixedExamVariants` принимает проверенный манифест, банк, записи проверки задач, постоянный `releaseId` и `createdAt`; возвращает не менее пяти вариантов либо пустой список с причинами блокировки.
- Каждая задача должна пройти `getPublicationDecision`, иметь подтверждённые баллы для данного номера и запись `TaskReleaseReview`, связанную с её ID, ревизией и SHA-256 всего содержимого, включая публикационные метаданные. Изменение текста после проверки делает запись устаревшей.
- Для развёрнутых ответов дополнительно требуются экспертная проверка и объяснение применимости конкретных критериев к авторскому прототипу. Авторский список рекомендаций нельзя переименовать в официальные критерии.
- Выбор воспроизводим при одинаковом `releaseId` и составе банка. Перестановка массива не меняет результат. Условия связанных групп (например, ОГЭ №1–5, если это подтверждено манифестом) сохраняются по одному `sharedConditionId`.
- Результат содержит фиксированные ID задач, хеши и версию структуры. Его нужно сохранить как отдельную редакцию, затем проверять через `validateFixedExamVariant`; при добавлении задач в банк старую редакцию не пересоздают. Изменённые или удалённые задачи требуют явного решения редактора.

Ни один из этих инструментов не публикует варианты, не меняет пользовательское хранилище и не подключает новые режимы к существующему экрану «Учебный вариант». Для включения нового выпуска ещё нужны реальные документы, проверенное наполнение, сохранённые манифесты и интеграционная проверка. Синтетические мини-экзамены в тестах проверяют только работу инструментов; они не являются опубликованными вариантами или сведениями о ФИПИ.
