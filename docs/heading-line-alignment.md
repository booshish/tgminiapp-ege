# Вертикальное выравнивание строки возврата

Причина: общий `.back-link { margin-bottom:16px }` из globals.css продолжал применяться к кнопке внутри `.practice-heading-row`. Flex align-items:center центрировал margin box, поэтому реальный текст возврата был выше текста метаданных примерно на 8px. При увеличенном шрифте дополнительно различались body-size и button-size.

Исправлены только два правила workspace-layout.css: одинаковый line-height 1.5 у строки, локальный margin:0 и наследование размера/line-height у её back-link. Gap20px и существующий flex-wrap сохранены; ни координат, ни transform, ни отрицательных отступов. Более специфичный selector действует только внутри этой строки. Панель контролов, карточка, bookmark, выход и его sticky, модели и сохранения не менялись.

Измерение: scripts/test-browser-heading-line.py использует DOM Range для реального текста кнопки и метаданных, а не только их внешние коробки. Chromium touch, профильная математика ЕГЭ, две темы, обычный/фокус, normal/large/huge, 320/375/390/768/820/1024/1440/1920; 1024×768 landscape, остальные высотой1000. Всего 96 случаев на версию. Разрешён перенос метаданных ниже кнопки, если они не помещаются; проверены отсутствие пересечения и document overflow. До: максимальное расхождение центров текста в одной строке 8.296875px, margin-bottom16px. После: 0px. Исходные JSON /workspace/scratch/heading-line-before.json и heading-line-after.json.

Настоящий Safari/iPad и системный Dynamic Type недоступны. Проверяются существующие увеличенные настройки шрифта приложения в Chromium, не заявляется проверка физического устройства. Другой браузерный regression taps дополнительно покрывает открытое/скрытое меню и переходы без перезагрузки.

Проверки и публикация фиксируются после завершения. Полный банк и несвязанные файлы не перечитывались; нет новых заданий, изменений ID, XP, фильтров, состояния или подписок.
