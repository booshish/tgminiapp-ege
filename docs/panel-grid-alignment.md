# Общая сетка панели практики

База b2f1fd9. Подтверждённое расхождение: PracticeWorkspace был block в обычном режиме и grid только в фокусе; для мобильного фокуса отдельно менялись width/flex чекбокса. Режимы разрешали перенос текста внутри кнопок; bookmark занимал отдельную строку перед заголовком. Это разные правила компоновки, а не проблема положения sidebar.

workspace-layout.css теперь задаёт общий grid с явными строками heading / controls / content в обоих режимах. Фокус только добавляет прежнюю 64px колонку выхода с gap12, без overlay. Первый ряд flex center с одинаковым gap, возврат неделим, длинное название направления может переноситься. Второй ряд flex center/wrap: переключатель и checkbox неделимы, кнопки центрированы inline-flex, тема и счётчик центрированы; длинная дополнительная подпись источника ограничена шириной строки и может переноситься, короткий счётчик переносится целиком. Заголовок и bookmark размещены в общей grid-строке TaskScreen; bookmark справа и не занимает отдельную вертикальную полосу. Общий левый край для обеих строк, h1 и карточки проверяется геометрически. Ни absolute, ни transform, ни координат относительно меню для текста нет.

Реальная sticky-кнопка остаётся самостоятельным элементом, старые caps карточки не возвращались. Задачи, taxonomy, hook состояния, XP, подписки, сериализация и React-компоненты не менялись. Автосброс остаётся НЕ реализованным, как в предыдущей контрольной точке; этот запрос его не добавляет.

Регрессия scripts/test-browser-practice-taps.py проверяет общий левый край и центр checkbox, nowrap кнопок режимов, оба режима оформления/меню, фокус/обычный без reload, single tap, черновик/reload/проверенный ответ, sticky и неперекрытие. Две темы, 320/375/390/768/820/1024/1440/1920, landscape1024×768. Дополнительно длинные DOM-подписи направления/темы и CSS zoom 100/125/150% при viewport820, не подменяя их заданиями или реальным browser zoom. Screenshots: /workspace/scratch/panel-grid-light.png и panel-grid-dark.png. Физический iPad/Safari и настоящий browser zoom недоступны; Chromium touch emulation, CSS zoom — ограниченная проверка масштабирования, не Safari-сертификация.

Проверки и публикация фиксируются после завершения. Основной изменённый файл — workspace-layout.css; браузерный regression test расширен. После обнаружения длинной подписи источника скорректирован перенос счётчика и повторены production build/затронутые браузерные сценарии; JS-логика не менялась.

Визуальная проверка дополнительно выявила legacy `.focus-mode .bookmark-button {display:none}`. Для практики оно переопределено по требованию доступности сохранения. При ширине самого TaskScreen <=20rem кнопка сохранения получает собственную явную строку под заголовком, чтобы не сдавливать h1; правило container query общее для обоих режимов. Шрифт не уменьшается. После этой окончательной CSS-правки повторяются сборка и затронутые браузерные проверки, не unit/TS без изменения JS. Пределы CSS zoom проверены отдельно в обычном/фокусе; это не проверка настоящего Safari zoom.
