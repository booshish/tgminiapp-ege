# Производительность практики «Точки» — 29.10.2026

Исходная версия: `49a1fd7`. Новых заданий нет. Количество, содержимое, стабильные ID, модели и taxonomy data сохраняются; `ege-math-profile` остаётся замороженным на 3603 активных номерных заданиях.

## Подтверждённая причина

`StudyApp` намеренно сохраняет `CatalogScreen` смонтированным под `hidden`, чтобы не терять положение списка. Изменение черновика обновляет родительский компонент и раньше заново запускало вычисления скрытого каталога. Его `availablePrototypes` проверял каждый прототип через `getPracticeTaskCount`. Каждый вызов снова объединял 4463 строки metadata index, создавал Set всех ID, проходил загруженный банк и вычислял выборку.

Сняты два CPU-профиля именно ввода: поддеревья `CatalogScreen` заняли **94,02% и 94,12% сэмплов**. Исходные минифицированные стеки сопоставлены с кодом: `getPracticeTaskIds`, `getPracticeTasks`, `getTaskView`, `getMetadataPlacement` и предикат `availablePrototypes`. Отдельный прогон без CPU-профайлера подтвердил 2211–2467 мс на одно нажатие при CPU ×4. Это воспроизведённая CPU-проблема, а не предположение о сети или «слишком большом банке».

## Внесённые изменения

- `src/lib/tasks.ts`: индексы существующих ссылок по экзамену/предмету/уровню, номеру, теме и прототипу. Metadata index и Map ID создаются один раз. Индекс загруженных разрешённых задач перестраивается после настоящего append. Запрос выбирает узкую группу вместо полного сканирования.
- В том же модуле: ограниченный LRU-кеш на 256 запросов по всем полям фильтра, с инвалидацией при регистрации пакета. `getPracticeTaskCount` читает длину без создания копии списка; `getPracticeTaskIds` возвращает отдельный изменяемый массив для сессии. Перестановка ID в сессии не изменяет кеш. Проверка доступности выполняется до использования кеша.
- Проверка регистрации пакета использует тот же pinned metadata index по ID. Сопоставление полей и публикационный gate сохранены; SHA256, число/порядок записей проверяются прежним loader.
- `src/components/screens/catalog-screen.tsx`: только вычисления доступных тем и прототипов сохраняются между рендерами. Зависимости — экзамен/предмет/уровень и ревизии append-only массивов задач/прототипов. Каталог остаётся смонтированным; scroll, выбор, управление, game/streak и навигация продолжают обновляться.

Ни UI, CSS, шрифты, тарифы, проверка ответов, ни сохранения не менялись. Записи черновика остаются немедленными: измеренная сериализация не была главным узким местом. Для 20 сессий / 40 черновиков / 161792 байт медиана полного `serializeStoredPractice` в Node составила 0,537 → 0,531 мс. КаТеХ и уже ограниченная 12 карточками лента не переписывались: сопоставимые замеры не показали там главной проблемы.

## Методика

Обе версии собраны через `npm run build:pages` и обслуживались одинаковым локальным HTTP-сервером. `/usr/bin/chromium`, viewport **390×844**, touch/mobile emulation, CDP **CPU ×4**, отключённый браузерный HTTP-кеш; пропускная способность сети не ограничивалась. Node — v24.19.0. Профилирующий сценарий работает в новых изолированных контекстах, не читает реальные браузерные данные ученика и ничего не отправляет на сервер.

По **два полных прогона** до/после, без сборки/тестов параллельно замерам. В каждом: холодный каталог ОГЭ-математики, открытие №9, посимвольный ввод, верный ответ, решение, **40 переходов**, черновики, закладка, тема/подтема/подтип/источник, «Все темы», лента из 12 полных условий, три страницы, открытие выбранной задачи и немедленный reload с проверкой последнего черновика. 80 переходов и 48 событий ввода на версию. «По одному» и «Лента» существовали до изменений и сохраняют прежние возможности.

Латентность действий измеряется до двух animation frames после результата. Это прикладная метрика стенда, **не Web Vitals INP/TTI и не React commit duration**. Cold catalog включает `networkidle` и ожидание интерактивной карточки номера. CPU-профайлер, PerformanceObserver longtask, CDP heap после GC и обёртки QA вокруг Storage.setItem / сериализации используются только в сценарии измерений. React production profiler не включался. Физический телефон, Telegram WebView и Safari здесь не измерены.

Исходные завершённые измерения и CPU profiles находятся в `/workspace/scratch/performance-before.json*` и `performance-after.json*`; переносимая агрегированная квитанция — `docs/performance-measurements.json`. При подготовке стенда отброшены незавершённые прогоны с тайм-аутом длинного ввода и ошибкой теста, который пытался менять уже проверенный readonly-ответ. Они не входят в итоговую статистику. В исходном измерении reload использовал часы разных документов; его время исключено из сравнения, восстановление состояния проверено функционально. Часы сценария исправлены для будущих запусков.
